# Headless Connect v1.0.0-preview.3

This preview fixes first-time enrollment and makes service-sharing instructions easier to follow. Each platform archive includes `datumctl-connect` and its matching `datum-connect-daemon`. This prerelease does not replace the production latest release.

## What changes

- Staging sessions use Datum's staging relays automatically. Enrollment waits for relay readiness instead of publishing an empty `homeRelay` that triggers HTTP 422.
- Connector updates retry HTTP 409 conflicts with fresh resource versions and ownership checks.
- Validation errors identify the operation, resource, and invalid fields. Structured logs report relay selection, readiness, timeouts, and conflict retries without exposing rejected values or credentials.
- `serve` explains access, gives your friend a concrete local port, and shows how to stop sharing using the original address. Existing device names and keys remain unchanged.

## Manually install the plugin with datumctl

You do **not** need `datumctl plugin install connect`. Download the binary, add it to PATH, and explicitly trust it. Install `datumctl` separately first; these instructions are verified with v0.20.0.

### Download and verify

Use `uname -s` and `uname -m` to select your archive:

| Platform | Archive |
| --- | --- |
| Apple Silicon Mac | `datumctl-connect_Darwin_arm64.tar.gz` |
| Intel Mac | `datumctl-connect_Darwin_x86_64.tar.gz` |
| Linux ARM64 | `datumctl-connect_Linux_arm64.tar.gz` |
| Linux Intel/AMD | `datumctl-connect_Linux_x86_64.tar.gz` |

For an Apple Silicon Mac, run the following. Change `CONNECT_ARCHIVE` for another platform. Check each step succeeds before continuing.

```sh
CONNECT_VERSION=v1.0.0-preview.3
CONNECT_ARCHIVE=datumctl-connect_Darwin_arm64.tar.gz
CONNECT_RELEASE_URL="https://github.com/datum-cloud/connect/releases/download/$CONNECT_VERSION"
CONNECT_DOWNLOAD_DIR=$(mktemp -d)
curl -fL --retry 3 "$CONNECT_RELEASE_URL/$CONNECT_ARCHIVE" -o "$CONNECT_DOWNLOAD_DIR/$CONNECT_ARCHIVE"
curl -fL --retry 3 "$CONNECT_RELEASE_URL/checksums.txt" -o "$CONNECT_DOWNLOAD_DIR/checksums.txt"
(cd "$CONNECT_DOWNLOAD_DIR" && awk -v asset="$CONNECT_ARCHIVE" '$2 == asset {print}' checksums.txt | shasum -a 256 -c -)
```

On Linux, you can substitute `sha256sum -c -` for `shasum -a 256 -c -`. Stop unless verification reports the expected archive as `OK`. Checksums verify integrity, not publisher identity. macOS binaries are unsigned and unnotarized; use the normal OS approval flow if blocked, without disabling security protections.

Extract into a persistent directory. Reuse an existing extraction rather than overwriting binaries currently used by a running service.

```sh
CONNECT_PREVIEW_DIR="$HOME/.local/share/datum-connect/previews/$CONNECT_VERSION"
mkdir -p "$CONNECT_PREVIEW_DIR"
tar -xzf "$CONNECT_DOWNLOAD_DIR/$CONNECT_ARCHIVE" -C "$CONNECT_PREVIEW_DIR"
chmod 755 "$CONNECT_PREVIEW_DIR/datumctl-connect" "$CONNECT_PREVIEW_DIR/datum-connect-daemon"
```

### Configure discovery and trust

```sh
export PATH="$CONNECT_PREVIEW_DIR:$PATH"
export DATUMCTL_PLUGINS_DIR="$CONNECT_PREVIEW_DIR/plugin-registry"
command -v datumctl-connect
datumctl plugin trust connect
datumctl connect --version
datumctl connect serve --help
```

Confirm that the trusted path points into your preview directory and the version is `v1.0.0-preview.3`. The separate registry prevents a managed Connect plugin from taking precedence over PATH. It isolates plugin discovery and trust, **not** your daemon, login sessions, or Cloud resources. Other managed plugins may not appear while this override is active.

For a new terminal, repeat these exports or add them to your shell startup file:

```sh
export CONNECT_PREVIEW_DIR="$HOME/.local/share/datum-connect/previews/v1.0.0-preview.3"
export PATH="$CONNECT_PREVIEW_DIR:$PATH"
export DATUMCTL_PLUGINS_DIR="$CONNECT_PREVIEW_DIR/plugin-registry"
```

Re-run `datumctl plugin trust connect` after replacing the plugin. If the wrong version runs, check `type -a datumctl-connect`, PATH, and the registry override. Do not overwrite files in the normal managed plugin registry manually.

### Share an application

For staging, sign in and select your shared project:

```sh
datumctl login --hostname auth.staging.env.datum.net
datumctl whoami
datumctl connect serve localhost:8080 --project datum-cloud
```

Replace `datum-cloud` if you use another project. Confirm that `whoami` shows `api.staging.env.datum.net`. Skip login if your current session is already correct. Start your application before `serve`.

In an interactive macOS/Linux user terminal, `serve` offers to download this release's daemon, install its background service, and enroll your device. You do not need a separate `up` or `install` command for a new setup. To install the daemon already in your archive instead of downloading it again, first run:

```sh
datumctl connect install --executable "$CONNECT_PREVIEW_DIR/datum-connect-daemon"
```

Keep this directory: the service references its executable by absolute path. This command does not replace an existing daemon. Do not run these per-user service commands with `sudo`. For an existing installation, follow the upgrade section.

### Connect from your friend's Mac

Your friend installs the same preview and signs in with their own account to the **same environment and project**. They run:

```sh
datumctl connect up --project datum-cloud
datumctl connect dial PEER_A_CONNECTOR:8080 --bind 18080 --project datum-cloud
curl http://127.0.0.1:18080
```

Replace `PEER_A_CONNECTOR` with the exact device name printed by the sender's `serve` or `status` command. Skip `up` if already connected. You can also copy the command printed by `serve`; use the local port it specifies. Change `--bind` if that port is occupied.

Your project needs exactly one ConnectorClass advertising `connect.datum.net/transport=masque-v1`; ask your platform administrator if it is missing. Installing this bundle does not create it. Direct peers do not need a MASQUE gateway. Services are private by default; `--public` requires a compatible gateway. Do not share credentials or local setup tokens with your friend.

## Upgrade from an earlier headless preview

**Replacing the plugin does not upgrade a running daemon.** After downloading and trusting this version, use these commands for a standard per-user macOS/Linux daemon:

```sh
datumctl connect daemon status
datumctl connect daemon stop
datumctl connect daemon uninstall
datumctl connect install --executable "$CONNECT_PREVIEW_DIR/datum-connect-daemon"
datumctl connect status --project datum-cloud
```

Keep a rollback executable and securely back up private state first. Stop/uninstall preserves configuration, credentials, and keys. Restarting briefly interrupts tunnels. Custom state paths, ports, system services, credential files, and IP approvals need their original installation settings preserved; do not replace them with these default commands. This is not a migration from the legacy desktop app or tunnel CLI.

If enrollment previously failed, run `datumctl connect up --project datum-cloud`, then retry `serve`. Do not delete your Connector or local state to clear a 409 or 422 error. The daemon still reports crate version `0.1.0`, so inspect the service's executable path rather than relying on that version alone.

## Diagnostics and limits

- Use `datumctl connect status` and `datumctl connect ping PEER_A_CONNECTOR --verbose` for diagnostics. Use `unserve HOST:PORT` on the sender and `hangup LOCALPORT` on the receiver to stop individual services or forwards.
- JSON logs live at `~/Library/Application Support/datumctl/connect/daemon/daemon.log` on macOS, or `~/.local/state/datumctl/connect/daemon/daemon.log` on Linux. Set `DATUM_CONNECT_RELAY_URLS` on the daemon service, not only the plugin's shell, if you need an override.
- Windows x86_64 and arm64 ZIP archives include the plugin, daemon, signed Wintun DLL, and license. Windows requires elevated service installation, a protected executable location, and renewable credential-file authentication—not interactive OIDC. Follow the [versioned platform guide](https://github.com/datum-cloud/connect/blob/v1.0.0-preview.3/docs/headless-preview.md).
- Production VPC enrollment and automatic upgrades remain unfinished. This preview makes breaking changes from the legacy tunnel CLI. Process tests on one host do not certify two computers across the internet or a production gateway deployment.

The attached [INSTALL.txt](https://github.com/datum-cloud/connect/releases/download/v1.0.0-preview.3/INSTALL.txt) includes full installation, upgrade, troubleshooting, and cleanup instructions. It also ships in every archive.
